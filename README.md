# 饭搭子 · 首尔团队午餐网站

手机和桌面均可使用的网页版，Node.js 后端 + SQLite 持久保存，无需安装依赖。

## 启动

需要 Node.js 22.13+（当前环境为22.23）。

```sh
# 首次安装时复制；若已有 .env，请直接修改，避免覆盖现有 Key。
cp .env.example .env
npm start
```

打开 http://localhost:3000 。当前开发环境已经配置现有 REST Key，不必重新复制 `.env`。

## Kakao 配置

`.env` 中分别配置：

- `KAKAO_REST_KEY`：后端调用 Local API，提供地址解析、地点搜索、附近餐厅搜索。不返回给浏览器。
- `KAKAO_JS_KEY`：可选，用于交互式地图。必须是 **JavaScript Key**，不能使用 REST Key。需要启用 Kakao Maps API，并在 Kakao 开发者后台登记实际 JavaScript SDK 网站域名，例如 `http://localhost:3000` 和部署后的 HTTPS 域名。

修改 `.env` 后重启服务器。原 `food_code.html` 作为旧版源文件保留，不作为当前网页提供。

Kakao 官方文档：[Local API](https://developers.kakao.com/docs/latest/ko/local/dev-guide)、[地图配置](https://apis.map.kakao.com/web/guide/)。

现有项目原文件中的 Key 经验证为 REST Key，已放入本机 `.env`；用户另行提供的 JavaScript Key 也已配置，并在浏览器中验证地图加载、餐厅标记和点击选址。未配置地图时，附近餐厅搜索、地址切换、随机选择和所有记录功能仍可工作。

## 使用流程

1. 首次打开自动创建团队空间。点击“邀请同事”复制带 `room` 的邀请链接；同一链接共享餐厅、位置、选择结果、日记和聊天。不同链接相互隔离。
2. 默认位置是 `서울특별시 서초구 강남대로89길 19`，由 Kakao 地址 API 解析。可搜索其他地址或地点，或授权浏览器使用当前位置。地图启用后也可点击地图选择位置。
3. 搜索 300m–2km 内真实餐厅，按距离最多读取45家。距离为直线距离，不是步行路线。
4. 点击“补充资料”填写菜单参考人均（韩币）和确认后的饮食类型。Kakao 不返回菜单价格或可靠的素食认证；未知资料明确标注，不伪造价格。默认允许价格待确认的餐厅参与随机，并明确提示可能超预算；关闭“允许抽到价格待确认的餐厅”后才按已确认人均执行严格预算。荤食／荤素筛选默认允许纳入类型待确认餐厅，并提示不保证满足所选饮食条件；取消对应开关后只使用已确认类型。素食筛选始终严格，包含纯素食餐厅及确认有素食选项的荤素餐厅，并额外搜索 비건 / 채식 / 샐러드 线索；未确认的线索单独展示，不参与素食随机。
5. 随机选店后向同事实时同步。再次随机时，存在其他候选则排除刚选的餐厅。
6. 每位同事记录自己的用餐日期、实际人均、1–5星口味评分、评价和照片。相同身份、相同餐厅、相同日期再次保存会更新原记录。支持补记往日用餐；不允许未来日期。
7. 用餐日记可按日期、个人/全团队筛选；统计包含人均消费、评分、菜系频次、餐厅口味榜、饮食类型分布及每位饭友的偏好。
8. 首页采用可爱的像素宇宙场景：深色点阵星空、彩色像素纸屑、带表情的星球、轨道动效和随机跃迁反馈；系统开启减少动态效果时会停止动画。每位匿名饭友第一次进入时会随机生成一个像素小人头像（猫、兔、熊、青蛙、小鸡、外星人等），点击右上角头像可「随机换个头像」并修改昵称，头像保存在服务器并显示在频道消息、首页漂浮气泡、用餐日记和偏好统计里。首页匿名输入框直接发消息，最近6条真实消息以漂浮气泡显示，点击气泡可查看完整频道。首页和完整聊天页使用同一后端，团队聊天使用 SSE 实时更新，断线后自动重连。匿名身份存于 HttpOnly Cookie；清除 Cookie 或换浏览器将创建新身份，原记录保留，但不能再作为原身份编辑。

照片在浏览器压缩至最长边1280px的 JPEG 后保存到数据库，允许原始 JPG/PNG/WebP，不接收 SVG。记录和聊天不会因刷新或重启丢失。统计的“消费合计”是每条个人记录的人均金额之和，不是整桌账单金额；多人同日评价分别计入，覆盖天数去重。

## 部署（Railway）

项目依赖长期运行的 Node 进程、SQLite 文件和 SSE 长连接，**不能直接部署到 Cloudflare Workers/Pages 或 Vercel 这类静态/边缘托管**（需要改用 D1 + Durable Objects 重写）。推荐 Railway：

1. Railway → New Project → Deploy from GitHub repo `boboni-cell/food`，分支 `main`。
2. Variables 里配置 `KAKAO_REST_KEY`、`KAKAO_JS_KEY`（**不要提交 `.env`**）；`PORT` 由 Railway 注入，`HOST` 默认 `0.0.0.0`。
3. 给服务挂载 **Volume 到 `/app/data`**。不挂载时容器文件系统是临时的，重新部署会丢失餐厅、日记和聊天记录。
4. Settings → Networking → Generate Domain，然后把该域名加入 Kakao 开发者后台的 **Web 平台域名**（JS SDK 用），否则地图不显示。
5. 健康检查路径 `/`；`railway.json` 已固定 Node 版本与启动命令。

## 后端与部署

- `server.js`：静态网页、REST API、匿名会话、Kakao 后端代理和 SSE。
- `public/`：原生 HTML/CSS/JavaScript，适合未来独立替换为 App 客户端；`public/avatar.js` 按头像种子确定性生成像素小人 SVG，不依赖图片资源。
- `data/lunch.sqlite`：餐厅、会话、每日记录、照片、聊天和团队设置。请备份整个 `data/` 目录；数据库运行中请使用 SQLite 备份工具或停机复制。
- `test/server.test.js`：多人独立评分、重复更新、团队隔离、非法输入、重启持久性和 SSE 同步的集成测试。

```sh
npm test
```

要让同事从手机访问，可以在同一 Wi-Fi 下用此电脑的局域网 IP 和端口3000访问；定位权限通常要求 HTTPS 或 localhost。公网使用需部署到支持 **长期 Node.js 进程 + 持久磁盘** 的服务，设置 HTTPS，反向代理禁用 `/api/events` 缓冲，并允许长连接。SQLite 和 SSE 的当前版本面向单实例的小团队，不适合无持久磁盘的静态托管或多实例部署。

这是“持有邀请链接即可访问”的匿名团队空间，链接等同访问权限，请仅分享给同事。当前完成本地可运行版本，尚未部署公网域名。
